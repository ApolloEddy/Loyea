Loyea 是一个运行在 Android 上的本地优先（local-first）的 AI 对话应用，源码开源。它把大模型对话与端侧物理感知、记忆系统、角色扮演（SillyTavern 人设卡兼容）、多模态能力结合，可通过 MCP（Model Context Protocol）让 AI 主动调用本地工具与联网工具。

当前稳定版：**v0.7.2**（Android 8.0 / API 26 及以上）。

> 本文档只描述当前代码中**已实际实现**的功能。未实现的功能不会出现在列表中。

## 下载与安装

安装包统一发布在 [GitHub Releases](https://github.com/ApolloEddy/Loyea/releases)，当前版本请进入 [Loyea v0.7.2](https://github.com/ApolloEddy/Loyea/releases/tag/v0.7.2) 下载 `Loyea-v0.7.2.apk`。

1. 下载 APK 到 Android 设备。
2. 如系统提示，允许当前浏览器或文件管理器「安装未知应用」。
3. 打开 APK 完成安装；v0.7.2 的内部 `versionCode` 为 16，可覆盖安装 v0.5.5 及之后的任意版本。

**从 v0.5.5 直接覆盖安装**：首次启动会自动执行一次性数据迁移——角色、会话消息、世界书、图谱记忆全部搬入新的 `rebuild_storage_v1/` 目录。迁移采用「staging 构建完成后原子切换」，旧文件原样保留、可随时回滚旧版；无法识别的旧扩展数据只读保留不丢弃。个别冲突数据（如同名旧版角色）会以「迁移冲突副本」条目出现在角色列表中，两份都在，自行取舍。

> Git 仓库只跟踪源码、测试和文档。APK/AAB 二进制安装包不会提交到源码树，均作为对应版本的 GitHub Release 附件分发。

## v0.7 架构重排：character-core 与数据迁移

v0.7 是一次底层重排，用户可见的变化集中在**角色系统**与**世界书**两块：

### 双模块架构

- `app`：聊天界面、物理感知、记忆、语音、MCP 等宿主能力（延续 0.5.5 的全部既有能力）。
- `character-core`：纯 Kotlin 静态模块，承载角色卡编解码（V1/V2/V3 PNG/JSON）、角色文档模型、世界书匹配内核、有限正则引擎与提示词编译器。不依赖 Android，可在 JVM 上完整测试。

### 统一角色文档

原生创建的人格与导入的 SillyTavern 卡使用同一种 `CharacterDocument` 存储：名称、人格、场景、系统指令、历史后指令、示例对话、备用开场白、内嵌世界书、正则脚本等全部字段原样保留。编辑与导入导出走同一条编解码链路，未知扩展字段保真不丢。

### 世界书 2.0：统一书库

散落三处的世界书（全局书 / 会话书 / 角色卡内嵌书）收敛为**一个书库**：

- **单一生效书语义**：任一时刻每个会话只有一本生效书。解析优先级为「会话绑定 > 随角色卡 > 全局生效 > 不使用」，全部入口共用同一次解析，不再有多层叠加的隐式行为。
- **条目级开关**：书库中每条条目可独立启停，含角色卡内嵌书的条目。
- **卡书条目可编辑（override 层）**：角色卡内嵌书的条目内容可修改，改动以快照形式存于书库 override 层，**角色卡原文件一个字节不动**；一键「恢复原文」回到卡内内容；删除卡后重新导入同卡，override 与开关自动恢复。
- **聊天页生效书面板**：聊天页右上角随时查看当前生效书（条目数 / 常驻数 / 来源），支持换书、跟随默认、跳转书库；换书在下一轮对话即时生效，流式输出中的当轮不受影响。
- **ST JSON 导入导出**：标准 SillyTavern World Info JSON 往返导入导出，含全部高级字段（selective 四逻辑 / 概率触发 / 递归链 / 分组 / `keysContainedIn` 多源扫描 / token 预算裁剪等）。
- **书级配置覆盖**：每本书可覆盖扫描深度、插入顺序、预算等匹配配置；未覆盖时继承全局默认。

### 有限正则（P5）

角色卡携带的正则脚本按「输入提示词 / 输出提示词 / 输出显示」三类作用域执行，基于 RE2/J 三阶段白名单映射：不支持的正则特性整条跳过并明确报告，有界执行防 ReDoS，卡原文保存保真。

### 提示词与缓存

- **固定顺序合同**：提示词各区块（系统指令 / 角色设定 / 世界书 / 记忆 / 工具说明）按确定顺序编译，两条请求路径（原生 / 导入卡）共用同一编译器。
- **字节级稳定前缀**：图谱记忆、底部世界书等易变上下文在用户消息发送时固化进不可变回合快照，后续请求逐字复用，扩大 DeepSeek 等服务商的前缀缓存命中。
- **历史滑窗按总上下文预算选取**：不再依赖固定「最近 20 条」，消除 20–160 条之间的摘要覆盖空档。
- **时间感知（用户消息时间线）**：开启系统时间后，每条用户消息在仅供模型的 payload 中携带发送时刻的绝对时间，配合回合快照中的当前时刻，模型可获得完整的时间流逝感；模型自身的历史回复不带任何时间标签。

## 功能总览

### 1. 对话与多模态交互

| 能力 | 说明 |
| :--- | :--- |
| 多模态输入 | 支持文本、语音、图片三种输入方式；图片走 Vision 模型理解，语音走 STT 转写或音频理解模型。 |
| Agent 式多轮回复 | 回复按「思考块 / 工具调用卡 / 文本段」分节内联展示，思考过程实时计时、结束后自动折叠。 |
| 重新生成回复 | 对 AI 回复不满意时点 ↻ 按钮重新生成，历史回复自动保存为版本，可用 `< N/M >` 翻页器切换回溯。 |
| TTS 朗读 | 文本转语音朗读，支持句中 `(温柔)`、`(哽咽)` 等语气标签；可开启"自动朗读"，横竖屏切换会延续当前播放。 |
| 生图 | 输入框以 `/draw 提示词` 或设置页触发图像生成。 |
| 长文本编辑 | 输入内容实际排版超过三行时显示全屏编辑入口；保留换行与现有发送/语音切换流程。 |
| LaTeX 渲染 | `$$...$$` 块级与 `$...$` 行内公式离线渲染（纯文本子集）。 |
| 时间分隔 | 当两条消息间隔超过 30 分钟时，居中显示本地化时间：当天 12 小时制，昨天/前天优先，再显示月日或年月日。 |
| HTML 状态面板 | 角色卡要求的状态面板（有限 HTML）原生渲染：文字、结构、折叠交互完整；无法渲染的内容折叠为「嵌入内容 · N 行 · 点击展开」降级展示，不把原始代码堆进对话。 |
| Token 用量控件 | 展开顶部模型选择器后，在下拉列表顶部显示用量头、环形图和上下文窗口占用条；按会话独立统计对话与系统调用 token（DeepSeek / OpenAI 读真实 usage，其余字符估算兜底），DeepSeek 前缀缓存命中率实时展示。 |

### 2. 角色系统

| 能力 | 说明 |
| :--- | :--- |
| 原生人格 | 不依赖任何卡即可创建、编辑、选用人格；内置人格支持用户覆盖。 |
| SillyTavern 卡全格式 | V1/V2/V3 的 PNG 与 JSON 导入；角色名、描述、人格、场景、系统指令、历史后指令、示例对话、备用开场白（可左右滑动切换）、内嵌世界书全部识别并保真保存。 |
| 卡内世界书 | 自动注册进统一书库，条目可见、可开关、可 override 编辑（见上文世界书 2.0）。 |
| 角色正则脚本 | 卡内 regex_scripts 经白名单映射后按三类作用域执行（见上文有限正则）。 |
| 风格优先级 | 「安全/隐私与工具授权规则 → 角色核心设定 → 性格/场景 → 示例 → 通用格式」顺序明确；角色卡要求的动作描写、状态面板格式不被宿主全局规则压制。 |

### 3. 端侧物理感知（MCP 本地工具）

大模型在对话中可自主调度以下传感器工具（均需用户开启对应权限与授权，见 [使用指南](#使用指南)）：

| 工具 | 感知维度 |
| :--- | :--- |
| `get_location` | 当前城市（用于本地化话题） |
| `get_live_weather` / `get_weather_forecast` | 当前气象 / 未来 3 天预报 |
| `get_environment_light` | 环境光照（Lux） |
| `get_battery_status` | 电量与充电状态 |
| `get_bluetooth_status` / `get_wifi_status` | 蓝牙外设 / Wi-Fi 连接 |
| `get_noise_level` | 环境噪音分贝（128ms 短时采样） |
| `get_activity_state` | 静止 / 步行 / 跑步 / 乘车 |
| `get_health_data` | 健康数据（仅经 Health Connect 按需读取，见下） |
| `send_voice_reply` | 让 AI 用语音回复 |

**防脑补机制**：当物理感知关闭时，工具列表与提示词中的物理信息会被彻底移除；历史用户消息中已固化的物理快照也会在发送前裁剪，防止模型"脑补"或继续读取旧的敏感状态。卡内虚构设定（如故事中的 HP、地点）不受影响。

### 4. 联网能力（Agent 式）

- **`web_search`**：多源容灾搜索（Bing ➜ 360 ➜ DuckDuckGo），源不可用时自动切换。
- **`read_url`**：直接抓取并提取网页正文（限读 1MB，自动识别字符集）。
- **联网搜索 API 全局配置**：在模型管理页顶部为所有模型统一配置一次搜索服务（或留空使用服务商自带联网 / 免 Key 检索）。
- 工具输出只作为**当次请求的临时上下文**，不写入永久对话历史；最近 10 分钟内的成功调用会以压缩片段注入提示词。

### 5. 记忆系统

| 能力 | 说明 |
| :--- | :--- |
| 知识图谱记忆 | 从对话中提取「主语—关系—宾语」三元组，本地 JSON 持久化；1-Hop / 2-Hop 召回，结合艾宾浩斯遗忘曲线衰减权重。 |
| 核心记忆 | 会话级手动编辑的锁定事实（★ 标记），AI 自动总结不会覆盖手动修改。 |
| 长会话压缩 | 滑窗按总上下文预算选取，窗口外旧消息自动压缩为早期摘要并保证覆盖连续，无静默空档。 |
| 世界书 | 统一书库（见上文世界书 2.0），替代旧的全局/会话双轨。 |
| 声学情绪感知 | 语音输入时识别音调情绪（伤心 / 生气 / 开心 / 温柔 / 中性等），以语气标签注入提示词。 |
| 后台提炼保活 | WorkManager 托管重型记忆提炼任务，进程退后台也能 15 秒内完成写入。 |

### 6. 模型与 API

| 能力 | 说明 |
| :--- | :--- |
| 多服务商 | DeepSeek / OpenAI / Kimi / Qwen / Groq / Ollama / Anthropic 及兼容中转，接口地址、Key、模型名自由配置。 |
| 模型列表云端同步 | 一键 GET /models 拉取可用模型，点选填入；本地 chips 仅作离线兜底。 |
| 多模态四卡 | TTS 语音合成、STT 语音转写、Vision 图片理解、ImageGen 图像生成各自独立配置（预置 MiMo / OpenAI / 阿里 / 火山等模板，支持自定义）。 |
| MCP 外部工具 | 外部 MCP 服务器接入，工具逐项授权白名单。 |
| 设置分区 | 设置页按「连接 / 模型 / 能力」三节组织，拉取状态与失败原因内联显示。 |

### 7. 健康数据集成（Health Connect）

- 厂商中立接口：读取系统「健康连接」（Health Connect）中的数据，适配任何会写入该系统的应用（重点适配**小米运动健康**、三星健康，Wear OS 同）。
- 设置页内置**配对状态面板**：SDK 状态、数据来源生态识别、各指标可用性、最近同步时间，一键连接。
- **不主动注入**：仅在「健康连接授权 + 健康工具授权 + 物理感知开关」全部满足时，AI 通过 `get_health_data` **按需获取**。

### 8. UI 与交互

- 暖沙色纸张质感主题，基于 YIQ 公式动态计算文字前景对比度；v0.7 起启用全新品牌图标（自适应图标，圆形/圆角方形遮罩均完整，含通知栏白色剪影）。
- 微信同款手势录音：按下录音、松开发送、上滑取消、右滑转文字。
- 智能会话标题：首条消息自动生成兜底标题，首轮回复后 AI 精修；支持手动重命名与手动触发 AI 重新生成。
- 角色按创建时间排序；主界面布局与交互习惯延续 0.5.5，高级功能收进设置与二级页面。

## 使用指南

以下按操作路径说明复杂功能的使用方法。

### 配置模型 API（第一步）

打开 **设置** 页，配置至少一个可用的模型服务：

1. **对话模型**：必填。在 API 配置中填写接口地址、Key，然后可在模型管理页「同步模型列表」一键拉取可用模型点选。
2. **多模态四卡**（可选，各自独立）：TTS 语音合成、STT 语音转写、Vision 图片理解、ImageGen 图像生成，每张卡可配置不同的服务商与模型模板。
3. **联网搜索**：模型管理页顶部「联网搜索 API（全局）」配置一次全模型共用；留空则回落服务商自带联网或免 Key 检索。
4. 部分功能有全局开关：自动朗读、音频理解、生图、声学情绪感知等，均可在设置中启用/停用。

> 未配置对应服务时，相关能力自动不可用；对话主模型不配则无法开始对话。

### 世界书：书库与生效

1. **入口唯一**：设置 ➜ **世界书**，进入统一书库（自建 / 导入 / 角色卡内嵌全部在列）。聊天页右上角的书图标可查看当前会话的生效书面板。
2. **新建/导入**：书库页 ➜ 新建 owned 书，或导入标准 SillyTavern World Info JSON；书详情页支持重命名、删除、导出。
3. **条目管理**：书详情页逐条开关、编辑（点条目正文可弹窗查看全文）；卡书条目编辑会存 override 层并标注「已改」，编辑弹窗内可「恢复原文」。
4. **让一本书生效**：在书详情页设「全局生效」（所有未绑定会话使用），或在某会话的生效书面板「更换本书」绑定该会话（最高优先）；「跟随默认」解除绑定回到自动解析。
5. **改完何时生效**：条目开关、内容编辑、换书均在**下一轮对话**生效；流式输出中的当轮不受影响。

### 启用物理感知

设置 ➜ **物理感知** 分组：

1. 打开「物理感知」总开关（该开关也决定是否向提示词注入物理工具说明）。
2. 对每个工具单独授权（位置、天气、光照、电量、蓝牙、Wi-Fi、噪音、运动状态、健康数据）。
3. 首次调用位置类工具时，系统会请求 Android 定位权限。

### 集成健康数据

1. 手机需装有会写入 Health Connect 的应用（如小米运动健康、三星健康）并完成同步。
2. 打开设置 ➜ 物理感知 ➜ **健康数据集成**，点「连接」完成 Health Connect 授权。
3. 开启「健康数据」工具授权与物理感知开关。
4. 之后 AI 在需要时通过 `get_health_data` 按需读取。

> 若面板显示"未授权 / 无数据"，请检查上述三步是否完整。本机生态若无数据源（如 OPPO 欢太健康不写 Health Connect），面板会标注不可用，属预期行为。

### 语音交互

- **语音输入**：按住输入框右侧麦克风，上滑取消、右滑转文字、松开发送。
- **语音纠错**：语音气泡双击/长按可重新转写（ASR）。
- **TTS 朗读**：AI 气泡上的 🔊 按钮朗读全文；在文本中插入 `(温柔)` `(哽咽)` 等标签可控制语气。
- **音频理解**：若当前模型支持音频输入，可直接发送语音让模型"听懂"，否则自动降级为 STT 转写。

### 重新生成回复与版本切换

1. 等 AI **回复完全结束后**，气泡下方才出现操作栏（流式输出中按钮与时间自动隐藏）。
2. 点 **↻ 重新生成**：生成新版回复，旧版自动保留。
3. 生成完成后该气泡显示 **`< N/M >`** 翻页器，点左右箭头在历史版本间切换。

### 会话标题管理

- **手动重命名**：侧边栏/抽屉会话列表 ➜ 每条会话右侧 ⋮ 菜单 ➜ 「重命名会话」。
- **AI 重新生成标题**：同一菜单 ➜ 「AI 重新生成标题」。
- 手动重命名后标题不会被 AI 自动覆盖；AI 标题可在首轮回复后自动精修一次。

### 记忆管理

- 侧边栏 ⋮ 菜单 ➜ 「查看核心记忆」：查看、编辑、新增、删除锁定事实；「手动总结」会针对弹窗对应的会话立即触发一次记忆提炼。
- 关系图谱记忆无需人工干预，在后台自动提取与清理。

## 安全与隐私

- **数据本地**：对话、记忆、配置均存储于设备本地 JSON；应用不开启云端备份，健康/位置/API Key 不外传。
- **数据迁移安全**：v0.7 迁移只读旧数据、原子切换、manifest 记录源文件快照（大小 + SHA-256），旧文件原样保留可回滚；迁移中断可重试，不会出现半新半旧的活动数据。
- **角色卡硬隔离与风格优先级**：内置角色受系统策略保护；导入的第三方人设卡内容仅作为角色数据，注入防注入围栏，卡片内索要敏感数据或强制调用的指令会被拒绝；合法角色风格中，核心设定的明确动作规则高于场景、示例与通用格式默认值。
- **正则有界执行**：角色卡正则脚本经白名单映射与三阶段有界引擎执行，恶意/错误表达式整条跳过并报告，不挂死 UI。
- **MCP 工具白名单**：外部 MCP 服务器暴露的工具可在设置中逐项授权；未授权工具不可见、不可调用。
- **敏感记忆过滤**：物理感知关闭时，涉及健康、位置等敏感关键词的记忆在写入与注入两端同时过滤。
- **原子写入**：本地文件采用「临时文件 + 重命名」原子写入，断电/杀进程不会产生半截数据；解析损坏时备份为 `.corrupt` 而非静默清空。
- **签名凭据不入库**：构建签名所需的 `keystore.properties` 与 keystore 文件已被 `.gitignore` 忽略，仓库中不包含任何签名密码。

## 构建与签名

```bash
# 需要 JDK 17
./gradlew.bat :app:assembleDebug   # 调试包
./gradlew.bat --no-build-cache --rerun-tasks :app:clean :app:testReleaseUnitTest :character-core:test :app:assembleRelease # 全量验证并生成发布包（需本地签名凭据）
```

发布签名：在项目根目录放置 `keystore.properties`（该文件已被 `.gitignore` 忽略），内容如下：

```properties
storeFile=../your-release.jks
storePassword=***
keyAlias=loyea
keyPassword=***
```

## 已知限制

- **世界书边界**：深度插入（at_depth）与 Author's Note 暂不支持（不支持的插入位置会记入诊断报告，不静默丢弃）；无向量召回、自动剧情状态机与多书叠加。世界书功能以 v0.7.2 的统一书库形态为准，不再扩展。
- **卡书条目增删**：角色卡内嵌书条目可开关与 override 编辑，但新增/删除条目仅对自建/导入书开放；卡书要改结构请导出为 owned 书再编辑。
- **健康数据**：OPPO 生态无公开健康数据接口，OPPO 专属采集线已停止投入；通用 Health Connect 接口依赖设备侧写入该系统，若无数据源则不可用。本仓库不计划为此更换或推荐特定硬件。
- **网页读取**：`read_url` 对依赖 JavaScript 动态渲染的页面可能提取不到正文（已内置该失败提示）。
- **外部服务依赖**：对话、语音、搜索均依赖第三方 API 的可用性；多源搜索会尝试容灾切换，但无法保证所有源始终可用。
- **模型遵循差异**：应用已在 system prompt 中定义角色风格冲突优先级，但第三方模型仍可能偶发偏离；代码测试只能验证 prompt 组装与顺序，最终表现需结合所选模型验收。
