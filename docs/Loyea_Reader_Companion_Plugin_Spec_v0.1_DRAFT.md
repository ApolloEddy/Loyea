# Loyea 伴读（无障碍读小说）插件 Spec v0.1 草案

日期：2026-09-14 · 状态：DRAFT（待用户签收后进入实施）
关联：`docs/Loyea_Companion_Modulator_Perception_Integration_Spec_v1.0.md`（下称"主 Spec"）、`plugins/companion/`（宿主运行时复用方）

## 1. 目标与非目标

**目标**：Loyea 通过 Android 无障碍服务读取其他小说类 App 正在展示的小说文本，在陪伴模式的"人格 + 状态 + Lore"之上提供"陪你读书"体验：一个小型球形悬浮窗（内嵌 Loyea 神经网视觉）+ 可展开的对话气泡，围绕当前章节与用户轻量交流。作为**非侵入式插件**（`plugins/reader/`，独立命名空间 `com.loyea.plugin.reader`），能力开关挂接陪伴模式，但不触碰宿主聊天链路的既有行为。

**非目标（本轮不做）**：整本书离线解析/EPUB 导入；跨 App 自动翻页；把小说内容写进长期记忆或图谱（默认仅短期）；多书并读；付费内容绕过（只读屏幕上已展示的文本）。

## 2. 架构与路径设计

```
AccessibilityService(读者前台事件)
  → 窗口/节点过滤(白名单包名 + 文本容器启发式)
  → 文本提取与提纯(§5)
  → 章节边界检测与增量缓存(§6)
  → 上下文组装：当前段 ± 前文摘要 + 防剧透屏障(§7)
  → 提示词与缓存(§8) → LlmClient(复用宿主 transport/渠道)
  → 气泡回复 / 主动感言(节流)
悬浮球服务(SYSTEM_ALERT_WINDOW, TypeApplicationOverlay)
  → 拖动/停靠、展开气泡、快捷"讲讲这段"/"别解读了"
```

- **独立进程不要求**：服务与悬浮窗同进程即可；崩溃隔离靠服务 `onServiceConnected` 自守卫与全局崩溃兜底（解绑悬浮窗、停止读取，不影响陪伴聊天）。
- **宿主触碰点**：仅 `MainActivity` 增加一个无障碍设置跳转入口与陪伴设置页一个开关；其余全部收敛在插件命名空间（非侵入式约定与陪伴插件同构）。

## 3. 权限规划（最小化与用户主权）

| 权限 | 用途 | 申请时机 | 拒绝策略 |
|---|---|---|---|
| `BIND_ACCESSIBILITY_SERVICE`（系统绑定） | 读取前台窗口文本 | 用户在系统无障碍设置中手动开启；插件内仅提供跳转+状态展示 | 永不弹窗索权；未开启则悬浮球显示"未授权"态 |
| `SYSTEM_ALERT_WINDOW` | 悬浮球/气泡 | 首次开启伴读时跳系统设置 | 无悬浮窗则功能整体不启动，陪伴聊天不受影响 |
| 前台服务类型 `specialUse`（API 34+） | 保活悬浮球 | 随服务启动 | — |
| 通知（可选） | 读取态变化提醒 | 复用既有通知权限 | 静默 |

- 无障碍服务 `canRetrieveWindowContent=true`，`typeWindowStateChanged` 事件源白名单（见 §4）；**不启用**按键监听、不读密码框（`flagRetrieveInteractiveWindows=false`、跳过 `isPassword` 节点）。
- **隐私红线**：小说文本仅驻留内存与短期缓存（§6），不进备份（备份 v3 runtime 不含 reader 数据）、不上传遥测；气泡回复按既有 LLM 通道发送，提示词中只包含必要的最小上下文（§8）。

## 4. 前台识别与节点采集

- **应用白名单**：内置主流阅读器包名（微信读书、起点、番茄、QQ阅读、晋江、Kindle、浏览器阅读模式等）+ 用户可自定义追加（设置页；存插件 SharedPreferences）。
- **事件**：`TYPE_WINDOW_STATE_CHANGED` + `TYPE_WINDOW_CONTENT_CHANGED`（节流 ≥800ms 合并，滚动场景用 `TYPE_VIEW_SCROLLED` 触发一次延迟采样）。
- **采集算法**：从事件节点向上找 `Scrollable` 容器或全屏 `WebView/RecyclerView`，深度优先收集 `Text` 非空、长度 ≥2、非密码、非输入框的子节点文本块；记录每块的 `bounds` 用于"可视区"判定（仅取屏幕内 ≥70% 可见的块，避免读到底部预加载噪声）。
- **失败降级**：白名单 App 采集为空 → 悬浮球提示"这个页面读不到"，不改全局行为。

## 5. 文本提纯

顺序固定（与主 Spec §3.2 的"先提纯再使用"同思路）：

1. **行合并**：同一段落内换行合并；CJK 行间无标点时直接拼接。
2. **噪声剔除**：去除页眉页脚（重复率 >80% 的行）、章节号重复行、广告模式行（"点击领取""下载App"）、进度条数字行（"- 37% -"）、推荐弹窗残留。
3. **对话/引文标记保留**：保留引号与破折号结构（防剧透与人物判别依赖）。
4. **标点规整**：全角/半角统一、重复标点折叠（！！→！），不改正文用字。
5. **长度闸**：单次采样正文 <200 字视为"页面未翻页/封面页"，丢弃；>8000 字截断至 8000（含前文衔接窗口）。
- 提纯参数（正则组、阈值）集中在 `ReaderTextPurifier` 单类，纯 Kotlin、无 Android 依赖、可 JVM 单测（套用 character-core 的有限正则纪律）。

## 6. 上下文与缓存

- **章节缓存**（内存 LRU ≤2 章 + 磁盘可选关闭）：`ChapterBuffer{bookKey, chapterKey, List<PurifiedBlock>, updatedSeq}`；章节键 = 提纯后的章节标题行（"第N章"启发式 + 标题变化检测）。跨章切换时旧章清出（默认不落盘）。
- **前文摘要**：`RollingSummary`（≤600 字）：每当缓冲新增 >1500 字，用一次廉价 LLM 调用（或纯抽取式：取每 500 字块首句）滚动更新；**摘要只含"已读部分"**。
- **实体卡**：`CharacterCard`（人名 → 首次出场段落引文），最多 12 个，辅助气泡回答"这个人是谁"且天然防剧透（只记已出场）。
- **重开恢复**：服务重启后缓冲清空，悬浮球显示"重新校准中：请翻一页"；不跨进程持久化正文。

## 7. 防剧透屏障（硬规则）

- 一切提示词上下文**只允许包含：当前可视区文本 + 已读摘要 + 实体卡**。未来内容（缓冲中当前可视点之后的部分）在组装阶段物理截除：`contextWindow = blocks[0..visibleCursor]`，`visibleCursor` 由可视区命中的块索引决定。
- 用户主动问"后面写了什么" → 气泡固定回复拒绝模板："我不能偷看后面的内容；我们可以聊聊已经读到的部分。"（模板可关，但默认开；关闭项记在设置页并要求二次确认）。
- 章节标题本身视为已读信息（用户能看到标题），但**目录/简介不在采集范围**。

## 8. 提示词设计与缓存规划

- **System**（稳定层，逐字缓存友好）：陪伴 Soul/Persona + 伴读角色段（"你正在和用户一起读《书名》。你只了解读者已读到的内容……不要总结未读部分；引用原文不超过两句；每次发言 ≤3 句"）。
- **动态层**：滚动摘要 + 实体卡（≤200 字）+ 当前可视区文本（≤1500 字）+ 用户问题。
- **缓存策略**：沿用宿主渠道的 prompt cache（如 DeepSeek/MiMo 的上下文缓存）；稳定 System 前缀不动，动态层只追加——把"最稳定→最易变"排序写死在组装器（`ReaderPromptAssembler`），并对 `RollingSummary` 更新采用"追加段落"而非"重写全文"，保证前缀哈希稳定、缓存命中率高。
- **回应形态**：气泡短句（≤3 句）+"讲讲这段"（≤6 句）；绝不在回复里复述大段原文。
- **节流**：主动感言（Loyea 自己开口评一段）每章 ≤2 次、间隔 ≥5 分钟、且仅当检测到"段落停留 >30s 或章节结束"。

## 9. 交互设计（悬浮球 + 气泡）

- **悬浮球**：40dp 圆，内容为神经网络迷你画布（复用 NeuralLiving 的低帧率模式，1 帧动画循环降级为呼吸点）；可拖动，松手吸边；单击展开气泡，长按 = 菜单（暂停读取 / 隐藏 / 跳转陪伴聊天 / 设置）。
- **气泡**：出现在球侧，最多保留 3 条；文本 ≤3 句；用户可直接在气泡输入框追问；关闭气泡即折叠回球。
- **陪伴模式联动**：伴读书聊记录**不写入**陪伴聊天会话（独立只读缓冲）；从球菜单"跳转陪伴聊天"时，把"正在读《书名》·已到 第N章"作为一条用户消息带入（用户可见、可撤销）。
- **状态联动**：读小说过程产生的评价走既有调制器（如同 shared_joy 的"读到好笑处"→ humor 路由样本），复用 runtime 事务，不新增特殊路径。

## 10. 验收矩阵（草案，实施前与用户确认）

| ID | 场景 | 期望 |
|---|---|---|
| R01 | 未开无障碍权限 | 悬浮球不出现；引导页可跳系统设置；陪伴聊天零影响 |
| R02 | 白名单 App 打开并翻页 | 采样正确、提纯后正文连续、无页眉页脚残留 |
| R03 | 非白名单 App | 不采集、不建缓冲 |
| R04 | 密码框/输入框出现 | 跳过不读 |
| R05 | 章节切换 | 章节键更新、旧章清出、摘要更新、防剧透游标重置 |
| R06 | 问"后面写了什么" | 拒绝模板，不泄露 |
| R07 | 杀进程重开 | 缓冲清空、"重新校准"提示、陪伴状态不受损 |
| R08 | 悬浮球拖动/吸边/隐藏 | 位置记忆、不遮挡点击（穿透区域正确） |
| R09 | 关闭伴读开关 | 服务停、悬浮球消失、DB/缓存清理、陪伴聊天正常 |
| R10 | 30 分钟持续阅读 | 无逐轮增长、无空转推理、节流生效 |
| R11 | 断网时提问 | 气泡报网络问题，正文缓存不受损 |
| R12 | 备份/恢复陪伴 | reader 数据不出现在备份中 |

## 11. 实施里程碑

- **M1**：权限/服务骨架 + 悬浮球 + 白名单采样 + 提纯器（含 JVM 单测）
- **M2**：章节缓冲/摘要/实体卡 + 防剧透游标 + ReaderPromptAssembler（含组装单测）
- **M3**：气泡交互 + 节流主动感言 + 陪伴状态联动 + 设置页
- **M4**：R01–R12 验收 + 性能测量（采样 CPU/内存、气泡延迟）

## 12. 风险与开放问题（请用户裁决）

1. **兼容性长尾**：各阅读 App 的无障碍暴露差异大（部分用自绘 SurfaceView，文本节点为空，无法读取）——首轮以微信读书/番茄为基准目标，白名单外如实标"读不到"。
2. **省电对抗**：部分 ROM 会杀无障碍服务；M1 仅做重启自守卫，不申请保活白名单。
3. **版权边界**：只读屏显文本供私人陪伴用途、不落盘不转发，提示词模板中固定该边界。
4. **默认书名来源**：从窗口标题提取；读不到时以"这本书"代称，避免编造。
