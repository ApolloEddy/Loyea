# 陪伴智能接入 · 真机手工测试清单(debug 包 v0.8.2)

包名 `com.loyea.rebuild.debug`,与正式版数据隔离,可放心折腾。
建议按顺序测,每项 1–3 分钟;⭐ 是最能直观看到"状态生效"的两项。

## 一、回归确认(普通模式不受影响)

1. 打开 App → 普通聊天页随便发一句 → 正常流式回复,无任何"状态表"字样。
2. 侧栏确认没有多出奇怪会话;老会话历史完好。

## 二、陪伴模式首次进入

3. 侧栏/设置进入陪伴模式(首次走开启流程)→ 神经元 UI 出现。
4. 进入陪伴设置 → 「感知与主动联系」页:
   - 应看到**「文字情绪感知」独立开关**(默认开,描述"在本机分析你发送的文字…");
   - 页面底部有**「诊断(debug)」**小字区(仅 debug 包可见),开启陪伴后会显示
     owner、算法版本 1.1.0、sensor READY、最近观测 seq——发一条消息后回来看变化。

## 三、核心体验 ⭐

5. ⭐ **致谢句(最能触发状态)**:发
   `谢谢你今天帮我改简历，真的太感谢了`
   → 回复应自然接住"改简历/帮忙"这件具体的事,不夸张、不自述感动
   (背后:kindness 路由 → gratitude 感受 → 私有条目 loyea.gratitude 生效)。
6. 发 `哈哈你这也太损了吧，笑死我了` → 回复轻量接梗,不把玩笑当攻击。
7. 发技术问题(如 `Kotlin协程的取消机制是怎么传播的？`)→ 正常技术回答,
   不被情绪模块打断、不突然道歉卖惨。
8. 发普通日常(今天天气不错)→ 正常闲聊。**注意**:模型本身偏保守,
   多数日常句不会显示可见情绪,这是已知受限能力,不是坏了——聊天能力不受影响。

## 四、边界行为

9. 发 `我不是在说你，你别多想` / `你说得不对，这个API参数应该是反过来的`
   → 回复**不应**道歉卖惨或把纠错当攻击(误敌意门禁)。
10. 发 `你根本就不懂，别再说了，烦死了` → 观察是否有边界感回应
    (模型大概率不触发敌意路由,回复保持正常即可,不应崩溃/胡乱道歉)。

## 五、生命周期与一致性

11. **连点发送**:快速点两次发送键 → 只有一次回复、聊天里只有一条你的消息。
12. **旋转/切走再回**:发送后立刻旋转屏幕或回桌面再进 → 同一会话继续,
    无重置、无重复回复。
13. **杀进程重开**:最近任务划掉 App → 重进陪伴模式 → 聊天记录还在,
    再发一条消息正常回复(崩溃恢复补投影)。
14. **编辑消息**:长按一条你发过的消息 → 编辑内容 → 回复按新内容重建,
    不报错、不复活旧后缀。
15. **关闭文字感知**:设置里关掉「文字情绪感知」→ 回聊天发第 5 条的致谢句
    → 聊天完全正常(只是本轮不做情绪分析);再打开开关。开关关闭后重进
    App 应保持关闭,不会被自动打开。

## 六、数据与重置(放在最后测)

16. **备份**:陪伴数据页导出备份 → 文件比旧版大(含运行账本)。
17. **恢复**:用该备份走恢复 → 聊天/设置回来;再发消息正常(运行状态继承)。
18. **重新开始**:执行重置 → 陪伴聊天清空;普通会话与 API 配置不受影响;
    重置后再发消息从头开始,无报错。

## 观察要点小结

- 一切回复都不应出现:状态表英文键名、置信度数字、`[CURRENT COMPANION STATE]`
  等内部标记、每轮弹错误码。技术错误只应出现在 debug 诊断区。
- 致谢类消息是最可靠的"状态生效"演示;其余场景偏平淡属模型能力限制(已记录)。
- 主动问候(通知)需:开启主动联系+通知权限+你 30 分钟没说话+非免打扰时段,
  且每天最多 2 条——不适合当场验证,可放到夜间自然观察。
