# Loyea 状态表示层与感知词表对齐规范

版本：v0.2  
修订日期：2026-09-09  
兼容来源：April Perception Demo 2.1.4 实际内嵌代码  
适用范围：生成层 Prompt 的 `aspect | state | intensity` 动态状态表

## 1. 范围与设计决定

本规范将状态表示层改为“共用感知词汇定义＋必要的状态层扩展”，替代 v0.1 中未经旧模型词表核对的独立选词方式。

保留既有决定：

- 总体架构为“感知 → 决策 → 生成”，本表是生成层的输入接口。
- Soul 承载稳定人格与价值观；表格承载运行时状态，与上下文、记忆、核心事实、Lorebook 和本轮行为指令共同使用。
- 本地状态演化沿用既定状态机；规则选择标签与强度，模板负责输出表格。
- 表格固定为三列，不增加必填的对象、原因或 expression 列。
- 保留关系感情、关系信任、背景心境、当前感受四个 aspect。
- 不因词表对齐而重训旧模型、改变旧输出头、增加远程调用或新增同等数量的底层参数。

本次对齐包括名称、编码、工作词义、强度语义及兼容关系。感知结果的主体、对象、时间范围和可信程度仍须保留；它们不因共用词汇而变成角色自身的状态。

本规范不确定状态池的具体维数、动态方程、数值分段阈值、标签进入与退出条件、衰减速度或强度校准函数。

## 2. 旧模型接口核对结果

### 2.1 核对来源与证据边界

本版直接读取 `AprilPerceptionDemo-standalone-2.1.4.html` 的内嵌元数据、前端标签注册表、中文显示字典及输出解码函数，不仅依赖研发历史摘要。

| 核对项 | 实际结果 |
|---|---|
| 内嵌元数据 schemaVersion | `2.1.0` |
| 前端解码返回的 schemaVersion | `2.1.1` |
| 前端解码声明 | 12 个输出头，合计 82 个 logits |
| 基础标签数量 | 8，包含 `neutral` |
| 细粒度标签数量 | 8 |

两个 schemaVersion 在文件中确实不同，接入时应同时记录模型元数据版本与解码输出版本，不可混称为一个版本。

已恢复的是标签、顺序、显示名称和分数处理逻辑。本次没有重跑模型，也没有验证其识别精度或完整训练标注口径。下文的工作词义是跨层接口约定，不冒充恢复出来的训练标注手册。

### 2.2 已确认的情绪词汇

顺序与旧代码一致；旧模型适配器必须保留顺序，不能按新文档排序重排 logits。

| 输出头 | 按原顺序排列的标签 |
|---|---|
| `basePresence` / `baseStrength` | `joy`, `affection`, `sadness`, `anger`, `fear`, `disgust`, `surprise`, `neutral` |
| `fineStrength` | `grievance`, `disappointment`, `loneliness`, `gratitude`, `relief`, `shame_guilt`, `frustration`, `anticipation` |

需要纠正此前摘要或 v0.1 中的兼容判断：

1. 旧模型的基础标签是 `affection`，不是 `liking`；旧中文显示为“喜爱”。
2. 旧细粒度标签是 `anticipation`，不是 `hope`；旧中文显示为“期待”。
3. 旧模型输出 `shame_guilt`，没有独立的 `shame` 与 `guilt` 输出头标签。
4. “委屈” `grievance` 与“孤独” `loneliness` 已存在于旧细粒度词表中。
5. 完整标签表现在已从实际代码恢复，不能继续将这些字段标为“词表未恢复”。

## 3. 共用词典与对齐原则

### 3.1 同义共用，近义不强并

同一概念使用同一英文标识与固定中文显示名称。相近但不能无损互换的概念分别保留，并注明关系。

- 直接共用旧词：例如 `joy`、`anger`、`disappointment`、`gratitude`。
- 保留旧模型的粗粒度词：例如 `shame_guilt`，不凭一个复合分数生成两个确定的细分状态。
- 保留必要扩展：例如 `curiosity`、`confusion`、`trust`，不声称旧模型已有这些独立输出。
- 不把词义相近当成数值可以直接互通的依据。

建议由一份公共词典维护 `state_id`、中文名称、工作定义和兼容关系；各层引用适用子集。旧模型的标签索引由独立适配器维护，不能因公共词典增加条目而改变旧模型解码。

### 3.2 共用词汇与作用范围

状态表中一行的含义由 `aspect + state` 共同确定。例如：

- `relationship_affect / affection`：角色对当前交谈对象相对持续的喜爱。
- `feeling / affection`：角色在当前情境中产生的喜爱感，可能指向人、事物或当前体验。

两者共用“喜爱”的核心词义，时间范围与对象解释不同，不能直接覆盖。若当前感受没有独立的情境依据，不为凑行数重复输出同一个喜爱状态。

默认状态主体为当前角色；关系态度默认面向当前交谈对象。其他具体原因和对象由上下文明确。无法确定归属的感知证据，不能直接转写为角色状态。

### 3.3 三种兼容等级

| 等级 | 含义 | 处理方式 |
|---|---|---|
| 词汇共用 | 旧代码已有相同标签，核心工作词义相容 | 复用标识；数值仍经过状态更新规则 |
| 有关但不等价 | 存在包含、粗细粒度或作用范围差异 | 保留区别，禁止无条件替换 |
| 状态层扩展 | 旧输出中没有同名的独立情绪标签 | 由状态机和其他可靠情境依据产生；不强制扩充感知模型 |

## 4. Aspect 与状态词表

### 4.1 字段与输出数量

| 字段 | 定义 |
|---|---|
| `aspect` | 本行状态所属角度 |
| `state` | 该角度下被显式指定的状态标签 |
| `intensity` | 内部状态强度，可在文字档位后附带归一化数值 |

| 大类 | aspect | 英文标识 | 输出约定 |
|---|---|---|---|
| 关系态度 | 关系感情 | `relationship_affect` | 常驻 |
| 关系态度 | 关系信任 | `relationship_trust` | 常驻 |
| 背景心境 | 背景心境 | `mood` | 常驻，默认一个主态 |
| 当前感受 | 当前感受 | `feeling` | 按需多行，默认零到两个显著感受 |

常驻项缺少可靠来源时填写 `未确定 / —`。当前感受确有必要时允许超过两项；默认数量是输出预算，不是互斥规则。

好奇、困惑等仍归入当前感受，不另设“认知感受” aspect。

### 4.2 关系感情：relationship_affect

| state | 英文标识 | 来源 | 工作词义 |
|---|---|---|---|
| 中性 | `neutral` | 共用基础词 | 对交谈对象没有明显好恶偏向 |
| 反感 | `aversion` | 状态层扩展 | 对交谈对象相对持续的负面感情 |
| 喜爱 | `affection` | 共用基础词 | 对交谈对象相对持续的正面感情与喜欢 |
| 爱 | `love` | 状态层扩展 | 由关系语义和经历支撑的深厚感情 |

- v0.1 的本系统标签 `relationship_affect/liking` 迁移为 `relationship_affect/affection`，中文“喜欢”统一显示为“喜爱”。这是本系统的兼容迁移，不表示旧模型存在 `liking`。
- 喜爱不因强度达到某个数值而自动变成爱；是否具有浪漫含义由 Soul 和关系事实确定。
- `aversion` 不强行更名为 `disgust`：前者表示持续的关系反感，后者表示厌弃感，不能无条件互换。
- 陌生、熟悉属于关系事实；友好、冷淡、疏远若描述本轮如何表现，交给已有行为指令。

### 4.3 关系信任：relationship_trust

| state | 英文标识 | 来源 | 工作词义 |
|---|---|---|---|
| 信任 | `trust` | 状态层扩展 | 对交谈对象的可信、可依赖性形成正面判断 |
| 不信任 | `distrust` | 状态层扩展 | 对交谈对象的可信、可依赖性形成负面判断 |

低强度信任不等于高强度不信任。尚未形成判断时使用 `unspecified`。判断的具体范围由上下文限定，不自动泛化到所有领域。

关系感情与关系信任分别表示，允许“喜爱但不信任”。旧模型的亲和、敌意或修复立场可以提供事件证据，不直接等于长期信任值。

### 4.4 背景心境：mood

| state | 英文标识 | 来源 | 工作词义 |
|---|---|---|---|
| 中性 | `neutral` | 共用基础词 | 没有明显的情绪底色 |
| 平静 | `calm` | 状态层扩展 | 相对安定、少紧张的背景状态 |
| 愉快 | `cheerful` | 状态层扩展 | 持续一段时间的轻快、愉悦底色 |
| 低落 | `gloomy` | 状态层扩展 | 持续一段时间的沉郁、消沉底色 |
| 紧绷 | `tense` | 状态层扩展 | 持续一段时间的心理紧张状态 |
| 烦躁 | `irritable` | 状态层扩展 | 持续一段时间的易受扰动、易不耐烦状态 |

- 中性表示没有明显偏向，平静表示存在安定状态，二者不互换。
- 背景心境须有独立的慢状态依据，不能将当轮 `joy` 改写成 `cheerful` 就当作心境更新。
- 背景心境与当前感受可以不同，例如低落时因一句话被逗乐。
- 本组不承担 Soul 的稳定人格职责，也不额外建立一份可独立漂移的人格基线。

候选数量不等于每轮输出数量，也不等于底层参数数量。扩展词只有在存在相应状态依据时才可输出，不要求首轮实现就能计算全部候选。

### 4.6 不能无损替换的标签

| 标签关系 | 对齐规则 |
|---|---|
| `shame_guilt` 与 `shame` / `guilt` | 复合分数不能直接拆成两个细分值。只有其他依据足以区分时，状态层才输出具体标签。 |
| `anticipation` 与 `hope` | 旧标签只确认显示为“期待”，不能据名称认定其训练范围与“希望”完全相同。保留两词，不建立无条件别名。 |
| `grievance` 与 `hurt` | 委屈侧重不公或误解，情感受伤的范围更广；保留两词。 |
| `loneliness` 与 `sadness` | 孤独侧重连接缺失，不直接降格为悲伤强度。 |
| `joy` / `amusement` / `excitement` | 分别侧重高兴、被逗乐、激动；不按强度互换。 |
| `interest` 与 `curiosity` | 内容有吸引力不一定意味着存在想追问的未知信息。 |
| `disappointment` / `frustration` / `despair` | 分别侧重预期落空、推进受阻、缺乏改善希望；不是同一状态的三档强度。 |

同一事件已能明确输出 `guilt` 或 `shame` 时，不再为同一依据重复输出 `shame_guilt`。其他相近词也不应仅为了增加细腻感而重复填表。

`grievance` 在旧模型中的中文标签是“委屈”，本规范沿用该含义；不将其翻译成怨恨，也不重新引入持久怨恨累计参数。

## 5. 强度语义与旧分数接入

### 5.1 状态表强度

| intensity 标识 | 中文显示 | 含义 |
|---|---|---|
| `none` | 无 | 明确指定该状态不存在或强度为零 |
| `mild` | 轻微 | 低强度 |
| `moderate` | 中等 | 中等强度 |
| `strong` | 强烈 | 高强度 |
| `very_strong` | 非常强烈 | 很高强度 |

intensity 只表示内部强度，不表示存在概率、分类置信度、外在表现、回复篇幅或注意力权重。多个状态的强度不需要相加为 1，强状态不会自动抵消弱状态。

可在同一单元格附带 0～1 的归一化状态强度，例如 `中等（0.46）`。非零数值到档位的分界仍待确定；文字与数值应来自同一映射规则。

### 5.2 旧接口中不同分数的真实含义

以下字段及处理方式已经在旧前端代码中核对。表中“可供输入”均不表示直接复制成角色状态。

| 旧输出字段 | 代码所表达的含义 | 接入约定 |
|---|---|---|
| `emotions[id].rawProbability` | `basePresence` logits 经 sigmoid 处理后的分数 | 作为存在性证据，不当强度 |
| `emotions[id].calibratedProbability` | 基础存在分数经逐标签温度与偏置校准 | 作为存在性证据；不代表状态强度 |
| `emotions[id].strength` | `baseStrength` 经 sigmoid 后的强度分数 | 可供状态更新规则参考，跨层数值标尺需校准 |
| `emotions[id].effectiveScore` | 概率经业务调节和 policyWeight 加权，另可能受语法规则改写 | 用于业务选择参考，不直接解释为概率或内部强度 |
| `fineStates[id]` | `fineStrength` 经 sigmoid 后的分数 | 可供细粒度状态更新参考；没有独立的细粒度存在概率输出与之配套 |
| 顶层 `confidence` | 基础标签中最高的 calibratedProbability | 不能当成所有输出头的统一置信度 |
| 顶层 `ambiguity` | 基础存在分数归一化后计算的熵 | 不与 `dimensions.ambiguity` 混用 |
| `dimensions.intensity` | 连续维度头中的整体强度分量 | 不复制到每一个情绪标签 |
| `dimensions.valence` / `dominance` | 解码后范围为 −1～1 | 不是 0～1 的单情绪强度 |
| `dimensions.arousal` | 解码后范围为 0～1 | 是唤醒度，不直接等于每个情绪的强度 |

代码使用 sigmoid 或名为 probability 的字段，不足以证明分数已经在目标场景中良好校准。本版不承诺感知层的 0.7 与状态层的 0.7 等义，也不规定“概率 × 强度”等新转换公式。

### 5.3 标签迁移与数值迁移分开

对既有状态存档做同义命名迁移时，例如本系统 v0.1 的 `liking → affection`，不因改名改变原有强度。

将感知分数用于更新角色状态时，则必须经过既定状态机的评价与更新规则。两种迁移不是同一操作。

## 6. 中性、未确定、无与省略

| 表达 | 含义 | intensity |
|---|---|---|
| `neutral` | 在指定 aspect 中，有依据地判断没有明显偏向 | `—` |
| `unspecified`，中文“未确定” | 系统没有提供可靠判断；所有 aspect 可用的占位标记 | `—` |
| 某个状态配合 `none` | 明确指定该状态强度为零 | 无；可附数字 0 |
| 未输出某个当前感受 | 本轮没有显式指定该感受 | 不产生对应行 |

`unspecified` 不属于角色的困惑情绪，也不是旧模型的 `unclear` 标签的直接替身。旧感知中的 `unclear` 只说明相应对象或事实性判断不清楚，状态层需结合其他依据决定是否能够提供状态。

旧感知中的 `neutral` 在适配器中保留。它不自动产生 `mood/neutral`，也不自动清空已有关系或心境。状态层不需要突出任何当前感受时，可以省略 feeling 行。

省略不等于零或反面状态。每轮表格按当前快照解释，不能自动继承旧表中本轮遗漏的显式条目；上下文仍可提供其他情感线索。

## 7. 其他感知输出的使用边界

以下信息继续由感知和决策部分消费，不为对齐词表而全部塞入三列表格。

| 感知信息 | 用途 | 表格处理 |
|---|---|---|
| 对话行为 `dialogueAct` | 理解陈述、请求、道歉、安慰等行为 | 不作为角色情绪 state |
| 人际立场 `stances` | 理解亲和、玩笑、撒娇、敌意、防御、脆弱、修复等信号 | 作为情境与策略依据；不新增必填 aspect |
| `speakerAffectTarget` | 判断说话者感受的指向 | 用于事件归属，不改变表格默认主体 |
| `utteranceFactuality` | 区分断言、否定、假设、转述等 | 作为证据条件，不能把提到某情绪当成其真实发生 |
| 被提及者相关输出 | 区分情绪体验者与被提及对象 | 用于归属；不直接写成角色内心 |
| 连续维度、歧义与攻击性 | 提供补充感知证据 | 不自动变成新状态参数或新表格行 |

接收旧模型的 dominance 等字段，不意味着本规范决定了状态层必须采用某一套连续坐标体系；底层参数取舍另行设计。

## 8. 生成层解释与示例

### 8.1 固定解释约定

以下文本可作为表格的固定解释：

> 表格描述角色当前被显式指定的内部状态。请结合 Soul、当前情境、上下文、记忆、Lorebook 与本轮行为指令共同理解。各行可以同时成立，强度表示内在感受，不规定必须表现多少。“未确定”表示系统没有提供判断，未列出的状态不等于零。以本轮表格为当前显式状态，不自动沿用旧表中的遗漏条目。请自然回应，无须逐项点名或表演状态。

该文本是接口约定，不构成生成质量或连续控制精度的实验证明。

### 8.2 关系稳定，当前事件带来愤怒与委屈

| aspect | state | intensity |
|---|---|---|
| 关系感情 | 爱 | 强烈 |
| 关系信任 | 信任 | 强烈 |
| 背景心境 | 紧绷 | 中等 |
| 当前感受 | 愤怒 | 中等 |
| 当前感受 | 委屈 | 轻微 |

本例的当前感受对应共用标签 `anger` 与 `grievance`。这表示角色经状态更新后处于这些状态，不表示检测到用户愤怒就让角色同样愤怒。

### 8.3 有依据的扩展状态

| aspect | state | intensity |
|---|---|---|
| 关系感情 | 喜爱 | 中等 |
| 关系信任 | 信任 | 强烈 |
| 背景心境 | 平静 | 中等 |
| 当前感受 | 好奇 | 强烈 |

`curiosity` 是状态层扩展，须有对应的状态或情境依据；旧模型没有同名情绪输出，不妨碍状态层使用这个词。

### 8.4 尚不能细分羞愧与内疚

| aspect | state | intensity |
|---|---|---|
| 关系感情 | 喜爱 | 中等 |
| 关系信任 | 信任 | 中等 |
| 背景心境 | 紧绷 | 轻微 |
| 当前感受 | 羞愧／内疚（未细分） | 中等 |

本例仅适用于状态层本身已有这种复合感受依据、但尚不能进一步区分的情况。不能仅因用户的 fineStates.shame_guilt 升高就照抄这张表。

## 10. 后续映射工作与验收边界

本规范解决词汇兼容与接口解释，后续仍需独立确定：

| 待定项 | 需要确定的内容 |
|---|---|
| 输入依据 | 各标签依赖哪些感知字段、状态、关系事实与事件信息 |
| 状态演化 | 进入、退出、驻留、恢复、衰减与累积规则 |
| 强度映射 | 数值标尺、校准方式与五档分界 |
| 多感受选择 | 显著性感受的选择与重复信息抑制 |
| 复杂关系 | 不同范围的信任判断、矛盾关系感情如何表示 |
| 标签效果 | 共用词与扩展词在目标回复模型上的理解和表现 |

接口核对应满足：

1. 旧输出按原始标签顺序解码，词典扩展不改变任何既有 head 的索引。
2. 共享词、扩展词、粗细粒度关系都有明确记录，不存在未经说明的隐式别名。
3. 概率、强度、业务分数与置信度不混用。
4. 复合标签不能被无依据细分，用户情绪不能被无条件复制成角色状态。
5. 新增候选不增加固定输出行数，也不要求同等数量的底层参数。

本版完成的是静态文件与词表核对，不是模型重测或生成效果验收。
